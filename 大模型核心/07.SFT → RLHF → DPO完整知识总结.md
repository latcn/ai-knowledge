## 2. 第一性原理：预训练模型为什么不是助手

### 2.1 预训练目标

预训练是 next-token 预测：

$$
L_{\text{pre}} = -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta(x_t \mid x_{<t})
$$

它只学数据分布，不区分：

- 指令和回答
- 好回答和坏回答
- 安全和有害内容

所以预训练模型是“续写机器”，不是“助手”。

### 2.2 SFT 的目标

SFT 在指令-回答对上继续做 next-token：

$$
L_{\text{SFT}} = -\frac{1}{|y|}\sum_{t=1}^{|y|} \log \pi_\theta(y_t \mid x, y_{<t})
$$

其中：

- $$x$$：指令
- $$y$$：回答
- 只对回答部分计 loss，不对指令部分计 loss

为什么只对回答计 loss？

> 让模型专注“扮演助手”，而不是连问题也一起学。

### 2.3 SFT 的局限

SFT 只能模仿人类示范：

- 如果示范有偏，模型就有偏。
- 如果示范不够好，模型就学不到更好。
- 如果多个回答都好，SFT 无法表达“哪个更好”。

所以 SFT 之后还需要 RLHF/DPO。

## 3. SFT：监督微调

### 3.1 数据形式

指令-回答对：

$$
(x^{(i)}, y^{(i)})_{i=1}^N
$$

例如：

- 指令：解释什么是 Attention
- 回答：Attention 是一种加权平均……

### 3.2 损失函数

$$
L_{\text{SFT}} = -\frac{1}{N}\sum_{i=1}^N \frac{1}{|y^{(i)}|}\sum_{t=1}^{|y^{(i)}|} \log \pi_\theta(y_t^{(i)} \mid x^{(i)}, y_{<t}^{(i)})
$$

只对回答部分计 loss。

### 3.3 SFT 训练细节：KV-Cache 与 Loss Mask

用户问题：

> SFT 在指令-回答对上训练，实际采用微调，矩阵分解。训练时虽然记录整个问答的所有的 KV cache，但只对回答的 token 做反向传播 loss 训练调整权重。

回答：

- **KV-Cache**：训练时，模型会并行处理整个序列（指令 + 回答），计算所有 token 的 KV。但因为训练是全序列并行，KV 是并行算出来的，不是“缓存”出来的。训练时不需要 KV-Cache，因为所有 token 一起算。
- **Loss Mask**：计算损失时，使用损失掩码（Loss Mask），只对回答部分的 token 计算损失并反向传播梯度，指令部分的梯度被屏蔽。
- **目的**：让模型专注“如何回答”，而不是学习“如何提问”，避免模型变成只会重复问题的“复读机”。

### 3.4 微调与矩阵分解

用户问题：

> SFT 实际采用微调，矩阵分解。

回答：

- **微调（Fine-tuning）**：宏观概念，指在预训练模型基础上，使用特定领域数据继续训练，使模型适应新任务。SFT 是微调的一种具体形式。
- **矩阵分解（Matrix Decomposition）**：微观技术，通常指 LoRA 等参数高效微调方法。LoRA 将大型权重矩阵分解为两个小矩阵的乘积（$$\Delta W = BA$$），微调时只更新这两个小矩阵，大幅减少可训练参数量和显存占用。
- **关系**：SFT 是“做什么”（任务目标），LoRA 是“怎么做”（一种高效技术手段）。

### 3.5 换条件

- 如果对指令也计 loss：模型会连问题也一起学，可能学成“复读机”。
- 如果只在回答部分计 loss：模型专注“扮演助手”。
- 如果数据质量差：SFT 会把坏习惯也学进去。

### 3.6 标失效

SFT 是“能对话”的保证，不是“对话得好”的保证。  
它不能表达偏好，不能超越示范，不能优化人类价值观。

## 4. RLHF / PPO：用人类偏好定义目标函数

### 4.1 先问

SFT 之后，怎么让模型更符合人类偏好？

### 4.2 RLHF 四个模型（本周唯一硬指标）

| 模型 | 角色 | 参数 |
|---|---|---|
| Actor | 被训练的策略（LLM） | 更新 |
| Critic | 价值模型，估计基线 | 更新 |
| Reward Model | 人类偏好训练的打分器 | 冻结 |
| Reference Model | SFT 模型，KL 约束锚点 | 冻结 |

#### Actor

被训练的 LLM，策略 $$\pi_\theta$$。

#### Critic

价值模型 $$V_\phi$$，估计基线，降低方差。

#### Reward Model

人类偏好训练的打分器 $$r_\psi(x,y)$$，输入指令和回答，输出标量奖励。

训练数据：

$$
(x, y_w, y_l)
$$

其中 $$y_w$$ 是更受偏好的回答，$$y_l$$ 是较差的回答。

Bradley-Terry 模型：

$$
P(y_w \succ y_l \mid x) = \sigma(r_\psi(x,y_w) - r_\psi(x,y_l))
$$

损失：

$$
L_{\text{RM}} = -\mathbb{E}_{(x,y_w,y_l)} \log \sigma(r_\psi(x,y_w) - r_\psi(x,y_l))
$$

#### Reference Model

SFT 模型 $$\pi_{\text{ref}}$$，冻结，提供 KL 约束。

### 4.3 PPO 目标

$$
\max_{\pi_\theta} \mathbb{E}_{x\sim D, y\sim \pi_\theta(y|x)}[r_\psi(x,y)] - \beta \mathbb{KL}(\pi_\theta(y|x) \| \pi_{\text{ref}}(y|x))
$$

其中：

- 第一项：最大化奖励。
- 第二项：KL 惩罚，防止偏离参考模型太远。
- $$\beta$$：控制惩罚强度。

PPO 的具体损失：

$$
L_{\text{PPO}} = \mathbb{E}\left[\min\left(r_t A_t, \text{clip}(r_t, 1-\epsilon, 1+\epsilon) A_t\right)\right] - \beta \mathbb{KL}
$$

其中：

- $$r_t = \frac{\pi_\theta(a_t|s_t)}{\pi_{\text{old}}(a_t|s_t)}$$：概率比。
- $$A_t$$：优势函数，由 Critic 和 Reward Model 估计。
- $$\text{clip}$$：限制策略更新幅度。

### 4.4 强化学习如何定义和调整误差

用户问题：

> 大模型训练时强化学习定义误差的大小或调整误差的大小？然后将这个调整后的误差再反向传播？

回答：

- **Reward Model 不直接“调整”误差，它负责“定义”误差的方向和大小。**
- Reward Model 根据人类偏好数据训练，给模型的不同回答打分。这个分数就是**奖励（Reward）**，量化回答的“好坏”。
- 在 PPO 等算法中，Reward Model 给出的分数不会直接用于更新模型参数。它会和 Critic 的预测一起，通过**广义优势估计（GAE）**等算法，计算出一个**优势函数（Advantage）**。
- 优势函数 $$A_t$$ 衡量：在当前状态下，采取某个动作（生成某个 token）比“平均预期”好多少。
- 这个**优势函数 $$A_t$$ 才是最终被反向传播、用来调整 Actor 模型权重的“调整后的误差”**。如果优势为正，则增加生成该 token 的概率；反之则降低。

所以：

> Reward Model 定义了奖励的“标尺”，优势函数将标尺的度量结果转化为可指导模型参数更新的“梯度信号”。

### 4.5 换条件

- 去掉 Reward Model：无法定义奖励，RLHF 无法进行。
- 去掉 Reference Model：没有 KL 约束，策略可能跑偏，reward hacking。
- 去掉 Critic：方差大，训练不稳定。
- 把 RLHF 当强化学习课学：会跑偏。它的本质是**用人类偏好定义目标函数**。

### 4.6 标失效

RLHF 的典型失败：

- reward hacking：模型学会欺骗奖励模型。
- 过度拒答：模型过度保守。
- 谄媚：模型迎合用户，不说真话。
- 多样性坍塌：模型只输出一种风格。
- 长度偏置：模型偏好长回答。

每一个都是“目标函数没写全”的表现。

## 5. DPO：直接偏好优化

### 5.1 先问

RLHF 太复杂，能不能去掉 Reward Model 和在线采样？

### 5.2 DPO 简化掉了什么

去掉：

- 显式 Reward Model
- 在线采样
- PPO 的复杂优化

保留：

- 偏好对数据
- Reference Model
- KL 约束（隐式）

### 5.3 从 RLHF 推导 DPO

RLHF 目标：

$$
\max_{\pi_\theta} \mathbb{E}_{x\sim D, y\sim \pi_\theta(y|x)}[r(x,y)] - \beta \mathbb{KL}(\pi_\theta(y|x) \| \pi_{\text{ref}}(y|x))
$$

最优策略有闭式解：

$$
\pi^*(y|x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y|x) \exp\left(\frac{1}{\beta} r(x,y)\right)
$$

其中 $$Z(x)$$ 是归一化常数。

反解奖励：

$$
r(x,y) = \beta \log\frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)
$$

代入 Bradley-Terry 偏好模型：

$$
P(y_w \succ y_l \mid x) = \sigma(r(x,y_w) - r(x,y_l))
$$

得到：

$$
P(y_w \succ y_l \mid x) = \sigma\left(\beta \log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)
$$

DPO 损失：

$$
L_{\text{DPO}} = -\mathbb{E}_{(x,y_w,y_l)} \log \sigma\left(\beta \log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)
$$

$$\beta$$ 控制偏离参考模型的惩罚强度（隐式 KL）。

### 5.4 为什么 DPO 不需要 Reward Model

因为奖励被表达成策略与参考模型的 log 比。  
不需要显式训练 Reward Model，也不需要在线采样。

### 5.5 为什么 DPO 还需要 Reference Model

因为 $$\beta$$ 那一项是隐式 KL 约束。  
没有 Reference Model，就没有“别跑太远”的锚。

### 5.6 换条件

- DPO 不需要 reward model，为什么还需要 reference model？→ 因为 $$\beta$$ 项是隐式 KL 约束，没有 reference 就没有锚。
- 把 RLHF 当强化学习课学，会怎样？→ 跑偏。它的本质是用人类偏好定义目标函数。
- 如果 $$\beta \to 0$$：无 KL 约束，策略可能跑偏。
- 如果 $$\beta \to \infty$$：策略几乎不变，学不到偏好。

### 5.7 标失效

对齐阶段的典型失败：reward hacking、过度拒答、谄媚、多样性坍塌、长度偏置。  
每一个都是“目标函数没写全”的表现。

## 6. GRPO：组相对策略优化

### 6.1 先问

PPO 需要 Critic，显存消耗大。能不能去掉 Critic？

### 6.2 GRPO 的核心思想

GRPO 由 DeepSeek 提出，是 PPO 的优化版本，核心是**去掉 Critic**。

- 对同一问题生成一组（Group）回答。
- 用组内回答的相对好坏（归一化后的奖励）来计算优势。
- 不需要 Critic 估计基线。

### 6.3 优点

- 省去一个模型（Critic），大幅降低显存占用和计算成本。
- 组内比较提供更稳定的优势估计。

### 6.4 缺点

- 较新的方法，泛化能力和最终效果仍在评估中。
- 在某些需要精细价值估计的复杂任务上，可能不如 PPO。

### 6.5 适用场景

资源有限，追求性价比。

## 7. 几种强化学习策略对比

| 特性 | **PPO** | **DPO** | **GRPO** |
|---|---|---|---|
| **核心思想** | 稳定优先，小步更新 | 直接优化偏好，绕过 RL | 去掉 Critic，组内相对优化 |
| **所需模型** | 4 个（Actor, Critic, RM, Ref） | 2 个（Actor, Ref） | 2 个（Actor, Ref） |
| **数据要求** | 在线采样，可交互 | 高质量的离线偏好对 | 对同一问题生成一组回答 |
| **显存消耗** | **极高** | **低** | **中低** |
| **训练稳定性** | **高**（但超参敏感） | **高**（简单分类问题） | **高**（组内归一化） |
| **主要优势** | 成熟、稳定、上限高 | 简单、高效、易实现 | 成本低、效率高 |
| **主要劣势** | 资源消耗大、训练慢 | 数据依赖强、泛化稍弱 | 较新，泛化性待全面评估 |
| **适用场景** | 资源充足，追求最佳效果 | 快速迭代，数据质量高 | 资源有限，追求性价比 |

## 8. 换条件与标失效总结

### 8.1 换条件

- SFT 只对回答计 loss，如果对指令也计 loss，模型可能学成“复读机”。
- DPO 不需要 reward model，为什么还需要 reference model？→ 因为 $$\beta$$ 项是隐式 KL 约束，没有 reference 就没有锚。
- 把 RLHF 当强化学习课学，会怎样？→ 跑偏。它的本质是用人类偏好定义目标函数。
- 如果 $$\beta \to 0$$：无 KL 约束，策略可能跑偏。
- 如果 $$\beta \to \infty$$：策略几乎不变，学不到偏好。
- 去掉 Reward Model：RLHF 无法进行。
- 去掉 Reference Model：策略可能跑偏，reward hacking。
- 去掉 Critic：方差大，训练不稳定。

### 8.2 标失效

- SFT 是“能对话”的保证，不是“对话得好”的保证。
- RLHF 的典型失败：reward hacking、过度拒答、谄媚、多样性坍塌、长度偏置。
- 每一个都是“目标函数没写全”的表现。
- DPO 是离线算法，依赖高质量偏好对数据，可能对数据分布偏移敏感。
- GRPO 较新，泛化性待全面评估。

1. SFT 后模型能对话，但不能表达偏好。
2. RLHF 后模型更符合人类偏好，但可能 reward hacking。
3. DPO 后模型效果接近 RLHF，但训练更简单。
4. 去掉 Reference Model，DPO 会跑偏。
5. $$\beta$$ 太小，策略跑偏；$$\beta$$ 太大，学不到偏好。
6. 对齐失败模式：reward hacking、过度拒答、谄媚、多样性坍塌、长度偏置。
7. GRPO 比 PPO 省显存，但效果可能略差。

## 14. 最终一句话总结

第 7 讲的核心不是“SFT、RLHF、DPO 是什么”，而是：

> 预训练模型是“续写机器”，不是助手。  
> SFT 用指令-回答对微调，只对回答计 loss，让模型学会“扮演助手”。  
> 但 SFT 只能模仿，不能表达偏好。  
> RLHF 用人类偏好训练 Reward Model，用 PPO 优化策略，KL 约束防止跑偏。  
> RLHF 四个模型：Actor、Critic、Reward Model、Reference Model。  
> DPO 去掉 Reward Model 和在线采样，把奖励表达成策略与参考模型的 log 比，直接优化偏好对。  
> $$\beta$$ 控制隐式 KL 强度。  
> GRPO 去掉 Critic，用组内相对优化，省显存。  
> 对齐阶段的典型失败：reward hacking、过度拒答、谄媚、多样性坍塌、长度偏置。  
> 每一个都是“目标函数没写全”。

这就是杠杆点 #7：

> 没有对齐，预训练模型只是“会说话”，不是“说人话”。  
> 有了 SFT、RLHF、DPO、GRPO，模型才能变成“听指令、符合人类偏好”的助手。
