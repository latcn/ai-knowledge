## ——按《学习方法论》手把手带一个本科生走完高杠杆节点

> 你现在不是"读"这十讲，是在"过"这十讲。
> 每一讲都用同一个循环：**先问 → 先猜 → 再看 → 换条件 → 标失效**。
> 先猜那一步不能跳。不猜，你读到的只是别人的结论；猜了，你才会知道自己的理解在哪断了。

## 第 0 讲：为什么必须按这个顺序学

先看这张依赖图，它决定了后面十讲的顺序：

```
分词 → Embedding → Attention → 多头 → Transformer Block
                                        ↓
                          残差/Pre-LN → 预训练目标（交叉熵）
                                        ↓
                              缩放定律 → 训练配方 → 并行
                                        ↓
                              KV-Cache → 推理优化
                                        ↓
                         SFT → RLHF/PPO → DPO → LoRA
                                        ↓
                              RAG → Agent（规划/工具/记忆）
```

**读图规则只有一条**：箭头左边不懂，右边学到的就是名词，不是知识。

- 不懂 Attention 去学 RoPE → 你只是在背"旋转位置编码"这六个字。
- 不懂交叉熵去学 DPO → 你只是在抄一个带 σ 的公式。
- 不懂 KV-Cache 去学量化 → 你只是在背"GQA 省显存"。

所以下面十讲，严格按依赖顺序走。每一讲都是一个节点，不是一篇文章。

## 第 1 讲：Attention 的本质（杠杆点 #1）

### 先问
没有 Attention，模型怎么处理上下文？

### 先猜（合上屏幕，写 30 秒）
我猜你会写"用 RNN"或"看前面的词"。这不算错，但没答到点上。
真正要问的是：**"看前面的词"这件事，用什么数学操作最自然？**

### 讲
答案是：**可学习的加权平均**。

- 每个位置提出一个 Query（我在找什么）
- 每个位置提供一个 Key（我是什么）
- 每个位置携带一个 Value（我有什么内容）

Q 和 K 做点积 → 相似度 → softmax → 权重 → 对 V 加权求和。

$$
\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

**为什么除以 $\sqrt{d_k}$？**
假设 $q_i, k_i$ 独立、均值 0、方差 1，则点积 $\sum_{i=1}^{d_k} q_i k_i$ 的方差是 $d_k$。
$d_k$ 越大，点积绝对值越大 → softmax 进入饱和区 → 梯度趋近 0 → 学不动。
除以 $\sqrt{d_k}$ 把方差拉回 1，softmax 留在敏感区。

### 换条件
- 不除以 $\sqrt{d_k}$，$d_k=64$ 时训练会怎样？→ 前期 loss 卡住，梯度极小。
- 不做 softmax 会怎样？→ 退化成线性加权，失去"选择性聚焦"，Attention 变成普通投影。
- $d_k$ 很小时（比如 4）不缩放行不行？→ 勉强能跑，因为方差本来就小。这说明"缩放"不是玄学，是方差控制的必然。

### 标失效
Attention 的复杂度是 $O(T^2 d)$。序列翻倍，计算量翻四倍。这是长上下文贵的根源，也是 FlashAttention、稀疏注意力、线性注意力存在的理由。

## 第 2 讲：Next-Token 交叉熵（杠杆点 #2）

### 先问
语言模型到底在优化什么？

### 先猜
"让预测更准"——太模糊。具体到公式是什么？

### 讲
训练目标：

$$
L = -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta(x_t \mid x_{<t})
$$

从最大似然推：
最大化 $\prod_t p_\theta(x_t \mid x_{<t})$ → 取 log → 取平均 → 加负号。

**它同时是四个东西**：
1. 训练目标
2. 评估指标（PPL = $e^L$）
3. 缩放定律的纵轴
4. 采样温度的来源（softmax 温度就是在调这个分布的平坦度）

**为什么等价于最小化 KL？**
$H(p,q) = H(p) + \mathrm{KL}(p\|q)$。$H(p)$ 是数据本身的熵，与模型无关。所以最小化交叉熵 = 最小化 KL。

### 换条件
- 换成 MSE 在 logits 上，会怎样？→ 梯度信号不对称，且和"概率分布"这个语义脱节，采样时没有意义。
- 只在回答部分计 loss（SFT 的常见做法），和全序列计 loss 差在哪？→ 前者让模型专注"扮演助手"，后者会连问题也一起学。

### 标失效
交叉熵只关心相对概率，不关心绝对概率。模型可以很自信地错。所以下游评估不能只看 loss，要看任务指标。

## 第 3 讲：残差 + Pre-LN（杠杆点 #4）

### 先问
为什么 100 层 Transformer 能训起来，而普通 100 层 MLP 会梯度消失？

### 先猜
"因为有残差"——对，但说不出机制等于没懂。

### 讲
残差：$h = x + f(x)$。
反向：$\frac{\partial h}{\partial x} = I + \frac{\partial f}{\partial x}$。

那个 $I$ 就是"梯度高速公路"——无论 $f$ 多深，梯度都有一条恒等路径直达浅层。

**Pre-LN 为什么比 Post-LN 稳？**
- Post-LN：$\text{LN}(x + f(x))$，归一化在残差之后，深层需要精细 warmup
- Pre-LN：$x + f(\text{LN}(x))$，归一化在子层输入前，梯度更稳，可以去掉 warmup

这就是为什么现代模型主流是 Pre-LN + RMSNorm。

### 换条件
- 去掉残差，20 层以上 loss 直接卡住。
- 把 Pre-LN 换回 Post-LN，不调 warmup 就训，前几百步会震荡。
- 初始化不按 $1/\sqrt{2n_{\text{layer}}}$ 缩放，深层输出方差爆炸。

### 标失效
残差不是万能的。它保证梯度能传，但不保证梯度"有用"。梯度能传到浅层，不代表浅层学到的表示是对的。

## 第 4 讲：训练配方四件套（杠杆点 #5）

### 先问
你的 loss 不降/爆炸/变 NaN，先查什么？

### 先猜
"调学习率"——这是最常见的错误答案，因为 90% 的问题不在学习率。

### 讲：诊断表

| 现象 | 最可能的 3 个原因 | 验证手段 |
|---|---|---|
| loss 一开始就不降 | lr 过大 / 数据标签错位 / 初始化错 | 打印 grad norm；用 10 条样本过拟合 |
| loss 中途出尖峰 | 坏 batch / 梯度爆炸 | 梯度裁剪；跳过该 batch；回滚 checkpoint |
| loss 变 NaN | fp16 溢出 / 除零 / lr 过大 | 换 bf16；检查 log(0)、√负数；逐层范数监控 |
| 验证集上升 | 过拟合 / 数据泄漏 | 查 mask；加 dropout；早停 |

**四件套**：
1. 初始化（GPT-2 风格 0.02 缩放）
2. 学习率调度（warmup + cosine）
3. 梯度裁剪（按全局范数）
4. 混合精度（bf16 优先）

### 换条件
- 模型放大 10 倍，warmup 要变长还是变短？→ 变长。大模型初期更脆弱。
- 换 bf16 后 scaler 还要不要？→ 通常不要，因为 bf16 动态范围和 fp32 一样。

### 标失效
这套配方是"能训"的保证，不是"训得好"的保证。训得好要靠数据、架构、规模。

## 第 5 讲：缩放定律（杠杆点 #3）

### 先问
给你 1e22 FLOPs，该训多大模型、喂多少数据？

### 先猜
"越大越好"——错。Chinchilla 说的就是这件事。

### 讲
- **Kaplan 2020**：loss 随参数量、数据量、算力呈幂律下降。
- **Chinchilla 2022**：给定算力，参数量和 token 数应**等比例增长**，约 20 token/参数。Kaplan 低估了数据的重要性。

训练算力估算：$C \approx 6ND$（$N$ 参数，$D$ token；前向 $2ND$，反向 $4ND$）。

### 换条件
- 为什么现在大家还在训远超 Chinchilla 最优的模型？→ Chinchilla 只优化训练算力。算上推理成本，"更小模型 + 更多数据"更划算；再算上绝对质量和下游价值，超配数据也合理。
- "涌现能力"是真的吗？→ 用不连续指标（精确匹配）看是突然出现；换成连续指标（token 级编辑距离）就是平滑上升。可能是指标造成的幻觉。

### 标失效
缩放定律只在无瓶颈区间成立。数据质量差、架构有 bug、训练不稳定时，幂律不适用。

## 第 6 讲：KV-Cache 与推理瓶颈（杠杆点 #6）

### 先问
为什么生成比训练慢？

### 先猜
"推理没优化好"——不对。是结构性的。

### 讲
训练：全序列一次并行前向。
推理：一次一个 token，每步都要读全部权重和 KV-Cache → **受显存带宽限制，不是算力限制**。

KV-Cache 缓存的是各层过去 token 的 **K 和 V**，不缓存 Q（Q 只属于当前位置）。
新 token 只算自己的 Q，然后和缓存的 K/V 做注意力。

显存估算：

$$
\text{KV bytes} = 2 \times n_{\text{layer}} \times n_{\text{kv\_head}} \times d_{\text{head}} \times T \times \text{bytes}
$$

乘 2 是 K 和 V。注意用 $n_{\text{kv\_head}}$ 不是 $n_{\text{head}}$。

**GQA**：分组共享 K/V 头，介于 MHA（每头独立）和 MQA（全部共享）之间。省的是缓存和带宽，不是注意力计算量。

### 换条件
- 不要 KV-Cache，每步重算所有历史 K/V → 每步 $O(T^2 d)$，总 $O(T^3 d)$。不可接受。
- 序列翻倍，KV-Cache 翻倍，注意力计算翻四倍。这就是长上下文贵的根源。

### 标失效
KV-Cache 省了计算，但没降总复杂度。它把"每步重算"变成"每步读缓存"，瓶颈从算力转到带宽。

## 第 7 讲：SFT → RLHF → DPO（杠杆点 #7）

### 先问
预训练的"续写机器"怎么变成"听指令的助手"？

### 先猜
"喂指令数据微调"——只说了 SFT。RLHF 和 DPO 解决的是什么？

### 讲
**SFT**：在指令-回答对上继续做 next-token，通常只对回答部分计 loss。

**RLHF/PPO 四个模型**（这张图是本周唯一硬指标）：

| 模型 | 角色 | 参数 |
|---|---|---|
| Actor | 被训练的策略（LLM） | 更新 |
| Critic | 价值模型，估计基线 | 更新 |
| Reward Model | 人类偏好训练的打分器 | 冻结 |
| Reference Model | SFT 模型，KL 约束锚点 | 冻结 |

**DPO 简化掉了什么**：去掉显式 Reward Model 和在线采样。把奖励表达成策略与参考模型的 log 比，直接得到偏好对上的闭式损失：

$$
L = -\mathbb{E}\log\sigma\!\left(\beta\log\frac{\pi_\theta(y_w)}{\pi_{\text{ref}}(y_w)} - \beta\log\frac{\pi_\theta(y_l)}{\pi_{\text{ref}}(y_l)}\right)
$$

$\beta$ 控制偏离参考模型的惩罚强度（隐式 KL）。

### 换条件
- DPO 不需要 reward model，为什么还需要 reference model？→ 因为 $\beta$ 那一项是隐式 KL 约束，没有 reference 就没有"别跑太远"的锚。
- 把 RLHF 当强化学习课学，会怎样？→ 跑偏。它的本质是**用人类偏好定义目标函数**。

### 标失效
对齐阶段的典型失败：reward hacking、过度拒答、谄媚、多样性坍塌、长度偏置。每一个都是"目标函数没写全"的表现。

## 第 8 讲：LoRA / 量化（杠杆点 #8）

### 先问
为什么单卡能微调大模型？

### 先猜
"因为 LoRA 参数少"——对，但为什么少还能有效？

### 讲
LoRA 的核心假设：**微调所需的权重更新是低秩的**。

$$
\Delta W = BA,\quad B\in\mathbb{R}^{d\times r},\ A\in\mathbb{R}^{r\times k}
$$

可训练参数 $= r(d+k)$ 每层。$r \ll d$。

- $B$ 初始化为 0 → 训练开始时 $\Delta W = 0$，模型行为和预训练完全一致
- $A$ 随机初始化 → 保证梯度不为零
- 缩放因子 $\alpha/r$ → 稳定不同 rank 下的有效学习率

**QLoRA 三件套**：4-bit NormalFloat 量化基座 + 双重量化 + 分页优化器。

### 换条件
- $r$ 增大到 $d$，LoRA 退化成全量微调。
- 两个都初始化为 0 → 永远不更新。
- 冻结 A 只训 B → 也能跑，但表达力受限。

### 标失效
LoRA 假设低秩。如果任务需要的更新本来就是高秩的（比如学一门新语言），LoRA 会欠拟合。

## 第 9 讲：RAG 全链路（杠杆点 #9）

### 先问
模型不知道的事，怎么让它知道？

### 先猜
"接个向量数据库"——这是最常见的浅层答案。

### 讲
链路：**chunk → embed → retrieve → rerank → compose → generate**。

难点不在向量库选型，在：
- **切块策略**：切断了语义单元，检索再准也没用
- **重排**：召回用双塔追速度，重排用交叉编码器追精度
- **上下文组织**：关键信息放中间会"迷失"

**五种具体失败模式**：
1. 切块切断语义
2. embedding 对否定/数字/专有名词不敏感
3. 召回正确但排序靠后
4. 上下文太长导致"迷失在中间"
5. 模型无视检索内容，凭参数知识编答案

### 换条件
- 什么时候 RAG 不如微调？→ 需要稳定行为、格式、语气、领域推理风格时。
- 什么时候必须 RAG？→ 需要最新、可更新、可溯源的事实时。

### 标失效
RAG 不改变模型的行为习惯，微调不保证事实准确。两者常组合，不是互斥选项。

## 第 10 讲：Agent 三件套（杠杆点 #10）

### 先问
LLM 怎么从"回答问题"变成"完成任务"？

### 先猜
"加工具调用"——只说了一半。

### 讲
**三件套**：规划、工具、记忆。

**ReAct 循环**：Thought → Action → Observation → 循环。

**五种失败模式**：
1. 死循环
2. 工具参数幻觉
3. 错误累积传播
4. 上下文爆炸
5. 把幻觉内容当工具结果

**评估必须报方差**：同一任务跑 3 次，方差常常大于方案之间的差异。只报单次成功率，选型结论不可靠。

### 换条件
- 不用框架手写 ≤150 行 ReAct，能跑通 → L3
- 能对陌生需求（"帮我把周报自动化"）给出 prompt/RAG/微调/Agent 的选择与代价 → L4

### 标失效
Agent 的瓶颈不在模型聪明不聪明，在**错误恢复**和**状态管理**。这两件事做不好，模型再强也会崩。

## 结课：三条永不改变的规则

学完这十讲，你手里应该有三样东西：

1. **一张手画的依赖图**（20 个节点以上，能说出任意相邻节点的"为什么必须先学"）
2. **一份失败模式清单**（每个节点至少 3 条，能复现）
3. **一个最小评估集**（15 个任务，跑 3 次报方差）

然后记住这三条，它们比任何具体知识都重要：

> **1. 每轮必须有可被别人检验的产出。**
> **2. 每个结论必须配一个变式或反例。**
> **3. 每个卡点必须外化并排入间隔检索，而不是留在脑内循环。**

---

你现在要做的第一件事，不是继续读，是**合上这份文档，在 A4 纸上画出那张依赖图**。
画不出来，说明你还在 L1。画得出来但说不清箭头为什么存在，说明你在 L2。
能画、能说、能指出哪条边最容易断——你才真正开始掌握。
