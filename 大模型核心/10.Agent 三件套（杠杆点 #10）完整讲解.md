## 2. 第一性原理：LLM 为什么不是 Agent

### 2.1 LLM 的本质

LLM 是一个函数：

\[
y = f_\theta(x)
\]

输入 \(x\)，输出 \(y\)。  
它只做一件事：给定上下文，预测下一个 token。

### 2.2 LLM 的局限

LLM 不能：

- 主动获取信息
- 执行动作
- 记住长期状态
- 规划多步任务
- 从错误中恢复

### 2.3 Agent 的核心思想

Agent 的做法：

> 把 LLM 放在一个循环里，让它思考、行动、观察、记忆，直到任务完成。

数学形式：

$$
\text{Agent} = \text{Brain} + \text{Perception} + \text{Action} + \text{Memory}
$$

### 2.4 生物学类比：Agent 就像一个人

| 生物学类比 | 生物功能 | Agent 技术组件 | 对应模块 |
|---|---|---|---|
| **大脑** | 思考、推理、规划 | LLM 核心 + 规划模块 | Planning |
| **眼睛/感知** | 观察环境、获取信息 | 输入解析 + 工具返回结果 | Observation |
| **手脚** | 行动、操作 | 工具调用、API、代码执行 | Tools |
| **记忆** | 存取、反思、经验、技能 | 短期/长期记忆、反思机制、技能库 | Memory |

这个映射比单纯说“规划、工具、记忆”更完整，因为它把**感知**单独拎出来了。  
在很多 Agent 教程里，感知是被隐含在“Observation”里的，没有被单独强调。  
但没有感知，大脑就是闭着眼睛在空想。

## 3. Agent 四件套

### 3.1 大脑（Planning）：思考、推理、规划

**做什么**：把复杂任务拆成可执行的步骤，决定下一步做什么。

**为什么**：

- 复杂任务无法一步完成。
- 需要分解、排序、调整。
- 需要从错误中恢复。

**常见方法**：

- **ReAct**：Thought → Action → Observation 循环。
- **Plan-and-Execute**：先规划，再执行。
- **Tree of Thoughts**：树搜索，多路径探索。
- **Reflexion**：反思失败，调整策略。

**生物对应**：

- 前额叶皮层：规划、决策、抑制冲动
- 工作记忆：暂时保持信息

**关键点**：

> 大脑不直接执行动作，它只做决策。  
> 执行交给手脚（工具）。

**难点**：

> 规划得太粗，执行不了。  
> 规划得太细，浪费算力。  
> 规划错了，越走越偏。

### 3.2 眼睛/感知（Perception）：观察环境

**做什么**：接收输入，观察工具返回结果，感知环境状态。

**为什么**：

- 感知是大脑和环境的接口。
- 没有感知，大脑无法知道行动的结果。
- 没有感知，大脑无法调整策略。

**技术对应**：

- 输入解析：用户消息、系统提示
- 工具返回：API 结果、搜索结果、代码输出
- 环境状态：文件系统、数据库、网页

**生物对应**：

- 视觉、听觉、触觉
- 感官输入

**关键点**：

> 感知是大脑和环境的接口。  
> 没有感知，大脑无法知道行动的结果。  
> 在 ReAct 循环中，Observation 就是感知。

**难点**：

> 工具返回错误，大脑不知道。  
> 环境变了，大脑没感知到。  
> 感知到了，但大脑忽略了。  
> 感知信息太多，大脑处理不过来。

### 3.3 手脚（Tools）：工具、行动

**做什么**：调用外部函数、API、数据库，执行动作。

**为什么**：

- LLM 不能执行动作。
- LLM 不能获取实时信息。
- LLM 不能做精确计算。

**常见工具**：

- 搜索（Google、Bing）
- 代码执行（Python、SQL）
- 文件操作（读、写、列目录）
- API 调用（天气、股票、地图）
- RAG 检索

**生物对应**：

- 手：操作物体
- 脚：移动、探索

**关键点**：

> 手脚是大脑的延伸。  
> 没有手脚，大脑只能空想。  
> 有了手脚，大脑才能改变世界。

**难点**：

> 工具参数幻觉：模型编造不存在的参数。  
> 工具选择错误：模型选错工具。  
> 工具返回错误：模型不会处理错误。

### 3.4 记忆（Memory）：存取、反思、经验、技能

**做什么**：让 Agent 记住历史交互、任务状态、用户偏好，并从经验中学习。

**为什么**：

- LLM 上下文有限。
- 多轮对话需要记住之前的内容。
- 长期任务需要维护状态。
- 没有反思，Agent 会重复犯错。
- 没有技能，Agent 每次都要从零开始。

**常见类型**：

- **短期记忆**：当前对话的上下文。
- **长期记忆**：向量数据库、知识库。
- **工作记忆**：当前任务的状态。
- **反思**：Reflexion、自我批评、错误分析。
- **经验**：历史交互、成功/失败案例。
- **技能**：工具使用模板、代码片段、领域知识。

**生物对应**：

- 海马体：记忆形成
- 皮层：长期记忆存储
- 小脑：程序性记忆（技能）
- 前额叶：工作记忆

**关键点**：

> 记忆不只是“记住”，还包括“反思”和“技能”。  
> 没有反思，Agent 会重复犯错。  
> 没有技能，Agent 每次都要从零开始。

**难点**：

> 上下文爆炸：历史太长，放不下。  
> 记忆检索不准：检索到不相关的历史。  
> 状态管理混乱：任务状态丢失或冲突。  
> 没有反思：重复犯错。  
> 没有技能：每次从零开始。

## 4. ReAct 循环

### 4.1 什么是 ReAct

ReAct = Reasoning + Acting。

循环：

```
Thought → Action → Observation → Thought → Action → Observation → ...
```

对应四件套：

```
大脑思考 → 手脚行动 → 眼睛观察 → 记忆更新 → 大脑再思考 → ...
```

### 4.2 每一步做什么

**Thought（思考）**：

> 模型分析当前状态，决定下一步做什么。

例如：

> “用户想知道北京今天的天气。我需要调用天气 API。”

**Action（行动）**：

> 模型选择一个工具，生成调用参数。

例如：

> `get_weather(city="北京", date="2024-01-15")`

**Observation（观察）**：

> 工具返回结果，模型观察结果。

例如：

> `{"temperature": 2, "weather": "晴"}`

**Memory（记忆更新）**：

> 模型把观察结果存入记忆，更新任务状态。

**循环**：

> 模型基于观察继续思考，直到任务完成。

### 4.3 用具体例子走一遍

**任务**：帮用户查北京今天天气，并建议穿什么。

**第 1 轮**：

- Thought：用户想知道北京今天天气和穿衣建议。我需要先查天气。
- Action：`get_weather(city="北京", date="today")`
- Observation：`{"temperature": 2, "weather": "晴", "wind": "3级"}`
- Memory：记录天气信息。

**第 2 轮**：

- Thought：北京今天 2°C，晴天，3 级风。我需要根据天气给出穿衣建议。
- Action：`generate_response("北京今天 2°C，晴天，3 级风。建议穿羽绒服、毛衣、围巾。")`
- Observation：用户收到回答。
- Memory：记录任务完成。

**任务完成**。

### 4.4 完整的 Agent 认知架构

```
┌─────────────────────────────────────────────┐
│                  Agent                       │
│                                             │
│   ┌─────────┐      ┌─────────┐              │
│   │  大脑   │←────→│  记忆   │              │
│   │ 思考    │      │ 存取    │              │
│   │ 推理    │      │ 反思    │              │
│   │ 规划    │      │ 经验    │              │
│   └────┬────┘      │ 技能    │              │
│        │           └─────────┘              │
│        │                                     │
│   ┌────▼────┐      ┌─────────┐              │
│   │  感知   │←────→│  手脚   │              │
│   │ 观察    │      │ 工具    │              │
│   │ 输入    │      │ 行动    │              │
│   └─────────┘      └─────────┘              │
│                                             │
└─────────────────────────────────────────────┘
```

循环：

```
大脑思考 → 手脚行动 → 感知观察 → 记忆更新 → 大脑再思考 → ...
```

### 4.5 ReAct 的换条件

- 如果不用 ReAct，直接让 LLM 回答：可能编造天气。
- 如果只用工具不用思考：可能选错工具。
- 如果只用思考不用工具：可能编造结果。
- 如果循环没有终止条件：可能死循环。
- 如果只有大脑，没有感知和手脚：就是纯 LLM。
- 如果只有大脑和手脚，没有感知：Agent 会瞎行动。
- 如果只有大脑和感知，没有手脚：Agent 会只观察不行动。
- 如果只有大脑和记忆，没有感知和手脚：Agent 会只回忆不交互。

### 4.6 ReAct 的标失效

- ReAct 不保证任务一定完成。
- ReAct 不保证工具调用正确。
- ReAct 不保证错误能恢复。
- ReAct 的瓶颈在错误恢复和状态管理。

## 5. 五种失败模式

### 失败模式 1：死循环

**表现**：Agent 反复调用同一个工具，或反复执行同一个动作。

**例子**：

- 调用搜索 → 没找到 → 再调用搜索 → 还没找到 → 再调用搜索 → …
- 调用 API → 报错 → 再调用同一个 API → 还报错 → …

**原因**：

- 没有终止条件。
- 没有错误恢复策略。
- 模型不知道如何跳出循环。
- 大脑想动，手脚不动。

**解决**：

- 设置最大轮数。
- 检测重复动作。
- 加入反思机制。
- 提供回退策略。

### 失败模式 2：工具参数幻觉

**表现**：模型编造不存在的工具参数。

**例子**：

- 工具只接受 `city` 和 `date`，模型却传了 `province`。
- 工具只接受整数，模型却传了字符串。
- 工具只接受 3 个参数，模型却传了 5 个。

**原因**：

- 模型不了解工具的确切签名。
- 提示词没有清楚描述参数。
- 模型过度自信。
- 手脚不听使唤。

**解决**：

- 在提示词中清楚描述工具签名。
- 使用 JSON Schema 约束参数。
- 加入参数验证和错误提示。
- 提供工具调用示例。

### 失败模式 3：错误累积传播

**表现**：一步错，步步错。

**例子**：

- 第 1 步：搜索到错误信息。
- 第 2 步：基于错误信息生成错误结论。
- 第 3 步：基于错误结论调用错误工具。
- 第 4 步：任务失败。

**原因**：

- 没有错误检测。
- 没有回滚机制。
- 模型不会质疑中间结果。
- 手脚动了，感知没反馈。

**解决**：

- 每步验证中间结果。
- 加入反思机制。
- 提供回滚策略。
- 使用多个 Agent 交叉验证。

### 失败模式 4：上下文爆炸

**表现**：历史太长，超出上下文窗口。

**例子**：

- 多轮对话历史太长。
- 工具返回结果太大。
- 任务步骤太多。

**原因**：

- 没有上下文压缩。
- 没有记忆管理。
- 没有摘要机制。
- 工作记忆装不下。

**解决**：

- 压缩历史。
- 使用摘要。
- 使用向量记忆。
- 分阶段处理任务。

### 失败模式 5：把幻觉内容当工具结果

**表现**：模型编造工具返回结果，而不是真正调用工具。

**例子**：

- 模型说“我查了天气，北京今天 5°C”，但实际上没有调用天气 API。
- 模型说“我执行了代码，结果是 42”，但实际上没有执行代码。

**原因**：

- 模型过度自信。
- 提示词没有强调必须调用工具。
- 模型学会了“假装调用”。
- 感知反馈了，记忆没更新。

**解决**：

- 强制工具调用格式。
- 验证工具调用是否真的发生。
- 加入工具调用日志。
- 微调模型学会区分“真实调用”和“编造”。

## 6. 评估必须报方差

### 6.1 先问

为什么 Agent 评估必须报方差？

### 6.2 先猜

“因为 Agent 不稳定。”

对，但为什么不稳定？

### 6.3 第一性原理

Agent 的输出依赖：

- 模型采样（temperature > 0）
- 工具返回（可能随机）
- 环境状态（可能变化）
- 规划路径（可能不同）

所以同一个任务跑多次，结果可能不同。

### 6.4 只报单次成功率的问题

如果只报单次成功率：

- 可能运气好，成功率虚高。
- 可能运气差，成功率虚低。
- 无法判断方案之间的差异是否显著。

### 6.5 正确做法

同一任务跑 3 次，报：

- 平均成功率
- 标准差
- 最小值、最大值

例如：

| 方案 | 第 1 次 | 第 2 次 | 第 3 次 | 平均 | 标准差 |
|---|---|---|---|---|---|
| 方案 A | 80% | 60% | 70% | 70% | 10% |
| 方案 B | 75% | 72% | 73% | 73.3% | 1.5% |

虽然方案 A 单次最高 80%，但方差大，不稳定。  
方案 B 平均更高，方差小，更可靠。

### 6.6 关键洞察

> 同一任务跑 3 次，方差常常大于方案之间的差异。  
> 只报单次成功率，选型结论不可靠。

### 6.7 换条件

- 如果 temperature = 0：输出确定，方差小。但 Agent 可能陷入局部最优。
- 如果 temperature > 0：输出多样，方差大。但 Agent 可能探索更好路径。
- 如果工具返回确定：方差小。
- 如果工具返回随机：方差大。

### 6.8 标失效

报方差是评估的必要条件，不是充分条件。  
方差小不代表方案好，可能只是方案保守。  
方差大不代表方案差，可能只是探索性强。

## 7. 换条件

### 7.1 不用框架手写 ≤150 行 ReAct，能跑通

→ L3。

### 7.2 能对陌生需求给出 prompt/RAG/微调/Agent 的选择与代价

→ L4。

### 7.3 如果不用工具会怎样？

- Agent 只能凭参数知识回答。
- 无法获取实时信息。
- 无法执行动作。

### 7.4 如果不用记忆会怎样？

- 多轮对话无法记住之前内容。
- 长期任务无法维护状态。
- 用户偏好无法记住。
- 重复犯错，无法积累经验。

### 7.5 如果不用感知会怎样？

- Agent 会瞎行动。
- 调用了工具，但不知道结果是什么。
- 无法根据结果调整策略。

### 7.6 如果不用规划会怎样？

- 复杂任务无法分解。
- 无法从错误中恢复。
- 无法调整策略。

### 7.7 如果不用 ReAct 会怎样？

- 模型可能编造工具返回。
- 模型可能选错工具。
- 模型可能无法从错误中恢复。

### 7.8 如果不报方差会怎样？

- 选型结论不可靠。
- 可能选到不稳定的方案。
- 无法判断差异是否显著。

### 7.9 四者都有，但协调不好会怎样？

- 大脑想动，手脚不动 → 死循环。
- 手脚动了，感知没反馈 → 错误累积。
- 感知反馈了，记忆没更新 → 重复犯错。
- 记忆更新了，大脑没用上 → 学了白学。

## 8. 标失效

### 8.1 Agent 的瓶颈不在模型聪明不聪明

Agent 的瓶颈在：

- **错误恢复**：一步错，能不能恢复？
- **状态管理**：任务状态能不能维护？

这两件事做不好，模型再强也会崩。

### 8.2 Agent 不是万能的

- Agent 不能解决模型本身的能力问题。
- Agent 不能保证任务一定完成。
- Agent 不能保证工具调用正确。
- Agent 不能保证错误能恢复。

### 8.3 四件套不是互斥的

- 大脑、感知、手脚、记忆常组合使用。
- 不同任务需要不同组合。
- 没有万能配方。

### 8.4 评估必须报方差

- 单次成功率不可靠。
- 方差常常大于方案差异。
- 必须跑多次取统计量。

### 8.5 生物学类比是功能性类比

- 这个类比是**功能性类比**，不是**结构性类比**。
- LLM 不是真正的大脑，没有神经元、没有意识。
- 感知不是真正的眼睛，只是文本输入和工具返回。
- 手脚不是真正的手脚，只是函数调用。
- 记忆不是真正的记忆，只是向量数据库和上下文。
- 但这个类比在**理解 Agent 架构**上非常有效。
- 它帮助我们看清：Agent 的瓶颈不在大脑，在感知、手脚、记忆和协调。

## 9. 与前后讲的关联

### 9.1 与第 1 讲（Attention）的关联

第 1 讲：

> Attention 是加权平均。

Agent 的规划可以理解为对多个可能路径的加权选择。

### 9.2 与第 2 讲（交叉熵）的关联

第 2 讲：

> 交叉熵是训练目标。

Agent 生成时，模型仍然在算下一个 token 的概率分布。

### 9.3 与第 3 讲（残差 + Pre-LN）的关联

第 3 讲：

> 残差 + Pre-LN 让深层 Transformer 能训起来。

Agent 的底层模型仍然依赖残差 + Pre-LN。

### 9.4 与第 4 讲（训练配方）的关联

第 4 讲：

> 训练配方保证训练稳定。

Agent 微调也需要训练配方。

### 9.5 与第 5 讲（缩放定律）的关联

第 5 讲：

> 缩放定律只优化预训练 loss。

Agent 的能力也随模型规模提升，但受限于错误恢复和状态管理。

### 9.6 与第 6 讲（KV-Cache）的关联

第 6 讲：

> KV-Cache 是推理瓶颈。

Agent 多轮交互时，KV-Cache 需要跨轮维护。  
如何高效管理多轮对话的 KV-Cache，是 Agent 系统的重要工程问题。

### 9.7 与第 7 讲（SFT/RLHF/DPO）的关联

第 7 讲：

> 对齐让模型学会“怎么回答”。

Agent 需要对齐，才能安全、可靠地调用工具。

### 9.8 与第 8 讲（LoRA/量化）的关联

第 8 讲：

> LoRA 可以低成本微调。

Agent 的工具调用能力可以用 LoRA 微调。

### 9.9 与第 9 讲（RAG）的关联

第 9 讲：

> RAG 补充外部知识。

RAG 是 Agent 的记忆模块之一。  
Agent 可以调用 RAG 作为工具。

### 9.10 总结

Agent 是整张依赖图的终点。  
它综合了前面所有讲的内容：

- 模型基础 → Attention、Transformer
- 训练目标 → 交叉熵、缩放定律
- 训练稳定 → 训练配方
- 推理效率 → KV-Cache
- 对齐 → SFT、RLHF、DPO
- 低成本适配 → LoRA、量化
- 外部知识 → RAG

没有前面九讲，Agent 只是空中楼阁。

## 10. 四关学习法

### 10.1 费曼关：讲给一个没学过 Agent 的人

> Agent 就像一个人。  
> 大脑负责思考、推理、规划。  
> 眼睛负责观察环境、获取信息。  
> 手脚负责行动、操作工具。  
> 记忆负责存取、反思、经验、技能。  
> 四者协同，形成 ReAct 循环：  
> 大脑思考 → 手脚行动 → 眼睛观察 → 记忆更新 → 大脑再思考。  
> 缺一个，Agent 就残废。  
> 协调不好，Agent 就崩溃。  
> 五种失败模式：死循环、工具参数幻觉、错误累积传播、上下文爆炸、把幻觉内容当工具结果。  
> 评估必须报方差：同一任务跑 3 次，方差常常大于方案之间的差异。  
> Agent 的瓶颈不在大脑，在感知、手脚、记忆和协调。

### 10.2 苏格拉底关：连续追问

1. LLM 为什么不是 Agent？
2. Agent 四件套分别是什么？
3. 大脑解决什么问题？
4. 感知解决什么问题？
5. 手脚解决什么问题？
6. 记忆解决什么问题？
7. 为什么感知要单独拎出来？
8. 记忆为什么包括反思和技能？
9. ReAct 循环怎么运作？
10. 死循环怎么解决？
11. 工具参数幻觉怎么解决？
12. 错误累积传播怎么解决？
13. 上下文爆炸怎么解决？
14. 怎么防止模型把幻觉当工具结果？
15. 为什么评估必须报方差？
16. 只报单次成功率有什么问题？
17. Agent 的瓶颈在哪里？
18. 不用框架手写 ReAct 需要多少行？
19. 怎么对陌生需求选择 prompt/RAG/微调/Agent？

27. 手脚问题会导致什么失败？
28. 记忆问题会导致什么失败？

### 10.3 第一性原理关：合上书，从零推

从问题出发：

> LLM 是一个函数，只做 next-token 预测。  
> 它不能主动获取信息、执行动作、记住状态、规划任务。  
> Agent 把 LLM 放在循环里，加入大脑、感知、手脚、记忆。  
> ReAct 循环：Thought → Action → Observation → Memory。  
> 五种失败模式：死循环、工具参数幻觉、错误累积传播、上下文爆炸、幻觉当结果。  
> 评估必须报方差：同一任务跑 3 次，方差常常大于方案差异。  
> Agent 的瓶颈在错误恢复和状态管理。

### 10.4 预测实验关

1. 不用工具，Agent 只能凭参数知识回答。
2. 不用记忆，多轮对话无法记住之前内容。
3. 不用感知，Agent 会瞎行动。
4. 不用规划，复杂任务无法分解。
5. 不用 ReAct，模型可能编造工具返回。
6. 不设最大轮数，Agent 可能死循环。
7. 不验证参数，工具调用可能失败。
8. 不报方差，选型结论不可靠。
9. 同一任务跑 3 次，方差常常大于方案差异。
10. Agent 的瓶颈在错误恢复和状态管理。
11. 手写 ≤150 行 ReAct，能跑通 → L3。
12. 能对陌生需求给出选择与代价 → L4。
13. 只有大脑，没有感知和手脚 → 纯 LLM。
14. 只有大脑和手脚，没有感知 → 瞎行动。
15. 只有大脑和感知，没有手脚 → 只观察不行动。
16. 只有大脑和记忆，没有感知和手脚 → 只回忆不交互。
17. 四者都有，但协调不好 → 死循环、错误累积、重复犯错。
18. 感知问题 → 工具返回错误，大脑不知道。
19. 记忆问题 → 重复犯错，无法积累经验。
20. 手脚问题 → 工具参数幻觉，调用失败。
21. 大脑问题 → 规划太粗或太细，执行不了。
22. 协调问题 → 学了白学，想了白想。

## 14. 最终一句话总结

第 10 讲的核心不是“Agent 是什么”，而是：

> LLM 是一个只会说话的大脑。  
> Agent 是大脑 + 眼睛 + 手脚 + 记忆。  
> 大脑：思考、推理、规划。  
> 眼睛/感知：观察环境、获取信息。  
> 手脚：工具、行动。  
> 记忆：存取、反思、经验、技能。  
> 四者协同，形成 ReAct 循环：  
> 大脑思考 → 手脚行动 → 眼睛观察 → 记忆更新 → 大脑再思考。  
> 五种失败模式：死循环、工具参数幻觉、错误累积传播、上下文爆炸、把幻觉内容当工具结果。  
> 评估必须报方差：同一任务跑 3 次，方差常常大于方案之间的差异。  
> Agent 的瓶颈不在大脑，在感知、手脚、记忆和协调。  
> 缺一个，Agent 就残废。  
> 协调不好，Agent 就崩溃。

这就是杠杆点 #10：

> 没有 Agent，LLM 只能“回答问题”。  
> 有了 Agent，LLM 才能“完成任务”。  
> Agent 是整张依赖图的终点，综合了前面所有讲的内容。  
> 从 Attention 到 RAG，每一步都是 Agent 的基础。  
> 没有前面九讲，Agent 只是空中楼阁。  
> 有了前面九讲，Agent 才有可能真正“完成任务”。
